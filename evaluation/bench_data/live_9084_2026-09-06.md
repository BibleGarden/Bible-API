# Живая проверка `POST /api/ai/question` на локальном 9084 (ClickUp 86cbehygb)

Дата: 2026-09-06. Контейнер `bible-api` перезапущен перед прогоном, баннер
показывает `key=set` на всех стадиях: `question`/`scripture_rewrite`/
`scripture_rerank` — `qwen3-30b-a3b-instruct-2507`, `transcribe` —
`deepdml/faster-whisper-large-v3-turbo-ct2`, эмбеддинги — `BAAI/bge-m3`, всё
на `llm.ai2.ru`. Промпт v4, поле `skipped_questions`, фильтр повторов и поле
`novel` — то, что лежит в `main`.

Это **протокол**, а не бенчмарк: один сэмпл на серию, 25 запросов всего.
Числа тут говорят «эндпоинт делает то, что описано», а не «столько-то
процентов». Замеры — в `evaluation/README.md`.

Обезличено: ключей, адресов и строк лога, кроме факта новизны, здесь нет.
Тексты входов уже опубликованы в `evaluation/question_series_inputs.json`
(разрешение Марии от 2026-09-05).

## Как снято

```bash
docker compose restart bible-api            # app/ смонтирован, процесс держал старый модуль
docker logs bible-api --tail 30 | grep key= # ни одного key=none
# ключ берётся из окружения контейнера и живёт только в окружении процесса:
#   BIBLE_API_KEY="$(docker exec bible-api sh -c 'printf %s "$API_KEY"')"
# 25 POST на http://127.0.0.1:9084/api/ai/question, по одному, с паузой 7 с
# (AI_REQUESTS_PER_CLIENT_PER_MINUTE=10)
docker logs bible-api | grep 'question novelty'
```

Серия = тело из `question_series_inputs.json` (тема + две пары вопрос/ответ
для `series-scale-ru`, одна пара для остальных), `stage: next`, пять запросов
подряд — «заменить вопрос» пять раз. В режиме **накопления** каждый
возвращённый вопрос уходит в `skipped_questions` следующего запроса; в режиме
**одинакового тела** поле не посылается вовсе — ровно то, что делает клиент
сегодня.

## Что видно в этом прогоне

1. **Фильтр ловит то, ради чего сделан.** `series-scale-ru`, накопление, шаг 2:
   модель вернула байт в байт вопрос шага 1, фильтр опознал (`repeat=exact
   score=1.00`), сервер сходил за вторым — и второй тоже повторился, поэтому
   ответ ушёл с `novel: false`. Это ровно тот случай, в котором клиент должен
   оставить на экране прежний вопрос, а не показывать этот текст как новый.
2. **Перегенерация иногда выигрывает.** `series-gratitude-ru`, шаг 4:
   `attempts=2 repeat=none novel=true` — первый ответ был помечен, второй
   оказался новым, человек увидел новый вопрос и ничего не заметил.
3. **Без накопления сервер повтора не видит, и это не его вина.** В режиме
   одинакового тела шаги 2 и 5 вернулись **дословно одинаковыми**, но оба с
   `novel: true`: `skipped_questions` пусто, сравнивать не с чем, а вопросы
   журнала (`assistant`-ходы) с этим текстом не совпадают (score 0.18). Поле
   ADR 0015 — не украшение: без него проверка повторов слепа по построению.
4. **Род держится.** Ни одного срабатывания эвристики рода на 25 ответах, в
   том числе в украинской серии, где v3 давал 30/30 (`зробив` женщине).
5. **Язык держится.** Английская серия — пять английских вопросов, украинская
   — пять украинских, при том что блоки инструкций сервер собирает по-русски.

## Что этот прогон нашёл в коде

Строки `question novelty:` в `docker logs` **не было вовсе**: первый прогон
(25 ответов) не дал ни одной. `trusted_proxies.ensure_visible_handler` вешает
обработчик на переданный ему логгер, а не на корневой, и `main.py` просил его
для `main` и `transcription`, но не для `twinkler_ai`; uvicorn корневой логгер
оставляет пустым, поэтому `INFO` глотался, а `WARNING` того же модуля (оба
тира правила отчаяния, отказы провайдера) доходил через last-resort handler —
из-за чего дыра и была незаметна. Исправлено одной строкой в `app/main.py`
рядом с такой же для `transcription`; прогон выше снят уже после этого, и в
нём 25 строк на 25 ответов.
